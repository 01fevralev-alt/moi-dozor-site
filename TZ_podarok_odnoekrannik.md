## 0. Как работать с этим ТЗ (экономия токенов)

1. **Не читай `index.html` целиком** — файл 199 КБ. Найди через grep и прочитай только:
   - блок `:root{...}` (цвета, радиусы, шрифт);
   - строку подключения шрифта Onest;
   - сниппет Яндекс Метрики (счётчик `99939047`);
   - JS отправки формы заявки (поиск по `lead-form`, `data-source`, адресу функции из `backend/lead-function`);
   - JS ссылок на мессенджеры и телефон (`data-phone-link`, `data-tg-link`, `data-max-link`, `data-wa-link`, `data-yandex-link`);
   - раздел целей Метрики («Metrika goals», `reachGoal`);
   - разметку блока видео (`.reel`, `.reels-track`) — откуда берутся видео и превью.
2. `podarok.html` — **отдельный файл**, весь CSS и JS внутри него. Основной сайт не меняем, кроме пункта 9.
3. Скрипты и проверки выводят только итог, без длинных логов.
4. **Репозиторий публичный.** Никаких токенов, ключей и паролей в коде. Секреты — только в Lockbox / переменных окружения функции.

## 1. Зачем страница

Сюда ведёт **только реклама в РСЯ** — ретаргетинг на людей, которые были на основном сайте и не оставили заявку. Задача — вернуть их и получить заявку за 1–2 касания.

Оффер: **9-канальный регистратор в подарок при договоре**. Подарок закрепляется за человеком на 7 дней с первого открытия страницы. Заявка «закрепляет» подарок за ним.

Страница **не индексируется** и **не связана** с основным сайтом:
- `<meta name="robots" content="noindex, nofollow">`;
- нет в `sitemap.xml`;
- нет ссылок с основного сайта;
- в `robots.txt` **не** запрещать (робот модерации Директа должен открыть страницу).

URL: `https://мойдозор.рф/podarok.html`

## 2. Дизайн

**Стиль = основной сайт.** Тот же шрифт (Onest, начертания 300–800), те же переменные из `:root`, тёмный фон `--bg`, янтарь `--accent` / `--accent-hi`. Новых шрифтов и цветов, кроме градиентов ниже, не вводить.

**Минимализм.** Владелец считает основной сайт перегруженным. Здесь — только суть. Никаких «Узнаёте?», сравнений, FAQ, лишних плашек. Если элемент не помогает оставить заявку — его нет.

**Одна смелая деталь — свечение первого экрана.** Мягкое градиентное свечение внутри первого экрана (не на стыках блоков, не на логотипе). Три варианта для выбора владельцем:

| Код | Название | Цвета |
|---|---|---|
| `a` | Янтарное свечение | `#E08A1E` → `#F2A13A` → растворяется в фон |
| `b` | Закат (по умолчанию) | `#E08A1E` → коралл `#F2664A` → винный `#5B1F3A` → растворяется в фон |
| `c` | Янтарь и слива | янтарное пятно `#E08A1E` + сливовое пятно `#6B3FA0` с другой стороны |

- Вариант выбирается параметром `?g=a|b|c`, без параметра — `b`.
- При `?preview=1` в углу появляется маленький переключатель A / B / C. Без `preview` переключателя нет.
- После выбора владельцем оставить один вариант, остальные удалить.

**Движение:** только тикающие секунды таймера и реакция на нажатия. Никаких появлений блоков при прокрутке. Уважать `prefers-reduced-motion`.

**Mobile first.** На экране 390 px первый экран целиком или почти целиком помещается без прокрутки.

## 3. Первый экран (весь текст, менять нельзя)

Порядок сверху вниз:

1. **Шапка:** знак-логотип (SVG `#i-logo` с сайта) + «Мой Дозор» слева; телефон справа, кликабельный `tel:`.
2. **Плашка рейтинга** (ссылка на карточку Яндекс Карт, `data-yandex-link`):
   `★ 5,0 на Яндекс Картах, 41 отзыв`
   ⚠ Число отзывов вынести в конфиг (п. 6). Перед публикацией сверить с карточкой.
3. **Заголовок H1** (зависит от отрасли, п. 5):
   `Ещё выбираете, кто установит видеонаблюдение?`
4. **Акцентная строка** (цвет `--accent-hi`, отдельной строкой, не часть H1):
   `Мы придержали для вас регистратор в подарок`
5. **Подзаголовок:**
   `Смета в 3 вариантах за 15 минут. Регистратор — бесплатно при договоре.`
6. **Таймер и счётчик** в одну строку (на мобильном — две):
   `Подарок закреплён за вами: 6 д 23:59:41` и `Осталось 7 из 10`
   Цифры крупные, табличные (`tabular-nums`), секунды тикают.
7. **Три вопроса — сразу кнопками-«чипсами»**, без «Далее», без выпадающих списков:
   - Объект: `Склад` `Цех` `База или ангар` `Другое`
   - Камер: `До 8` `8–16` `Больше 16` `Не знаю`
   - Когда: `В этом месяце` `В ближайшие 3 месяца` `Пока изучаю`
   Одно нажатие — вариант подсвечен янтарём; повторное — снимает выбор. **Вопросы не обязательны.**
8. **Контакт:** поле телефона с маской `+7 (___) ___-__-__` + кнопка `Закрепить подарок` (стиль `.btn-accent` с сайта).
9. Под ним строка: `или напишите в` + кнопки `MAX` `Telegram` `WhatsApp` (п. 7).
10. **Мелкий текст:**
    - раскрывающаяся ссылка `Условия акции` (`<details>`), текст — п. 8;
    - согласие: `Нажимая кнопку, вы даёте согласие на обработку персональных данных и соглашаетесь с политикой.` — ссылки на `consent.html` и `policy.html`, как на сайте.

**Ниже первого экрана — только одно:** 3 видео с объектов выбранной отрасли (по умолчанию — смешанные). Подпись под каждым — одна строка вида «Склад, 12 камер». Видео грузятся лениво, по нажатию. Затем подвал: ИП, ОГРНИП, телефон, почта, ссылка на политику.

**Не использовать в текстах:** «аванс», «без НДС», «охрана / охраняем», «лучший», «№1», марку регистратора, названия клиентов, цифры вроде «180+ объектов».

## 4. Таймер, промокод, счётчик подарков

**Личный срок (честный, не сбрасывается):**
- При первом открытии записать в `localStorage`: `podarok_start` (время) и `podarok_code` (промокод вида `RT-7K4M`, 4 символа без похожих букв/цифр).
- Срок = старт + 7 суток. Таймер считает до этого момента.
- Повторные визиты показывают тот же срок и тот же промокод.
- Если `localStorage` недоступен — срок считается от текущего визита, страница работает.

**После истечения срока** первый экран меняется:
- H1: `Срок подарка закончился`
- Подзаголовок: `Но смета в 3 вариантах за 15 минут — как и раньше.`
- Таймер и счётчик скрыты, кнопка: `Получить смету`. Вопросы и форма остаются. В заявку уходит пометка «подарок истёк».

**Счётчик подарков** — из файла `podarok-config.json` рядом со страницей:
```json
{
  "month": "2026-10",
  "gifts_total": 10,
  "gifts_left": 7,
  "min_contract_rub": 0,
  "reviews_count": 41,
  "max_bot_url": "",
  "active": true
}
```
- `gifts_left = 0` → вместо счётчика `Подарки на этот месяц закончились`, оффер как после истечения срока.
- `active: false` → страница показывает обычный оффер (выключатель акции).
- ⚠ `gifts_total`, `gifts_left`, `min_contract_rub` — **заполняет владелец**. До заполнения не публиковать.
- Позже (проект рекламы) значение будет обновляться автоматически из amoCRM — сейчас не делать.

## 6. Отправка заявки

- Использовать **ту же функцию и тот же JS-механизм**, что основная форма сайта (`backend/lead-function`). Не писать новый обработчик.
- `source`: `podarok`.
- Передавать всё, что передаёт основная форма (UTM, `yclid`, ClientID Метрики, страница), **плюс**:
  - `promo` — промокод;
  - `gift_status` — `active` / `expired` / `sold_out`;
  - `answers` — ответы на вопросы текстом, например `Объект: Склад; Камер: 8–16; Когда: В этом месяце`;
  - `gift_deadline` — дата окончания срока.
- **amoCRM:** промокод и статус подарка должны попасть в сделку. Проверь, какие поля сейчас заполняет функция. Если для промокода нет поля — допиши функцию так, чтобы промокод, статус и ответы шли в примечание к сделке, и в отчёте напиши владельцу, что для отдельного поля «Промокод» его нужно создать в amoCRM.
- Валидация телефона как на сайте. Ошибки — понятным текстом под полем: `Проверьте номер: нужно 10 цифр после +7`.

**Экран после успешной отправки** (заменяет форму):
- `Подарок закреплён за вами. Ваш промокод: RT-7K4M`
- `Смету пришлём в течение 15 минут в рабочее время — ежедневно с 9:00 до 20:00.`
- `Пока ждёте — посмотрите объекты, похожие на ваш:` + 2–3 видео выбранной отрасли.
- Кнопка `Получать смету и новости в MAX` — только если в конфиге задан `max_bot_url` (бота сделаем позже; ссылку дополнить параметром с промокодом). Если не задан — кнопку не показывать.
- Мелкая ссылка: `Наш канал в Telegram` → канал с сайта (`data-tgch-link`).

## 9. Цели Метрики (+ одна правка основного сайта)

**Новые цели на `podarok.html`** (JS-события, `ym(99939047, 'reachGoal', ...)`):

| Идентификатор | Когда |
|---|---|
| `podarok_view` | страница открыта |
| `podarok_answer` | выбран первый ответ на вопрос |
| `podarok_lead` | заявка успешно отправлена |
| `podarok_msg` | нажат мессенджер |
| `podarok_call` | нажат телефон |
| `podarok_expired_view` | открыта страница с истёкшим сроком |

**Цели активного визита — на всех страницах сайта** (нужны для сегментов ретаргетинга):
- `active_60` — 60 секунд **активного** времени: вкладка видима (`visibilitychange`) и за последние 15 секунд было действие — прокрутка, движение мыши, касание, нажатие клавиши.
- `active_120` — 120 секунд активного времени **и** прокрутка не меньше 50 % страницы.
- Каждая цель срабатывает один раз за визит.
- Сделать маленьким отдельным файлом `active-goals.js` и подключить одной строкой в `index.html`, `sklady.html`, `proizvodstvo.html`, `territorii.html`, `dom.html`, `mkd.html` и `podarok.html`. Больше ничего на основном сайте не менять.

**Создание целей в Метрике:**
- Если в окружении есть OAuth-токен с правом `metrika:write` — создай цели через Management API Метрики (тип «JavaScript-событие»), сначала проверив, что цели с такими идентификаторами ещё нет.
- Если токена нет — выведи владельцу короткую инструкцию: Метрика → Цели → Добавить цель → JavaScript-событие → идентификатор из таблицы.

## 10. Технические требования

- Вес страницы без видео — до 300 КБ. Видео и превью — ленивая загрузка.
- Один файл HTML с CSS и JS внутри + `podarok-config.json` + `active-goals.js`.
- Доступность: видимый фокус, `aria-pressed` на чипсах, подписи у поля телефона, контраст текста не ниже, чем на основном сайте.
- Поле телефона: `class="ym-hide-content ym-disable-keys"`, как на сайте (номер не пишется в Вебвизор).
- Публикация — тем же способом, что и остальной сайт.
